# MoodTrack 项目优势、音乐修改特色与技术边界说明

> 文档版本：1.0  
> 对应版本：2026-08-13  
> 面向对象：产品介绍、项目答辩、合作沟通与技术评估

## 1. 项目定位

MoodTrack 是一个以“情绪如何随时间变化”为核心的 AI 音乐共创系统。它并非只让用户输入一句风格描述后等待一首随机音乐，而是把创作过程拆成可编辑的情绪轨道、场景、音乐方向、时长、节奏、调性、歌词和局部修改等环节，再由生成模型完成音乐表达。

当前系统包含两条独立的生成链路：

| 能力 | 当前引擎 | 作用 |
|---|---|---|
| 普通纯音乐与人声歌曲 | 本地 ACE-Step 1.5 Turbo + 1.7B 5Hz 歌词 LM | 根据文本、情绪轨道、编曲方向、BPM、调性、时长及歌词生成音乐 |
| 局部重绘 | 本地 ACE-Step 原生 Repaint | 在保留原作品其余部分的前提下，重做指定时间段 |
| 视频配乐 | 本地 GVMGen + FFmpeg | 根据视频画面生成新配乐，并输出 WAV 与带新配乐的视频 |
| 文本情绪理解 | MoodTrack Text Emotion Agent | 将开放式情绪表述归纳为可解释的标准情绪信息，同时保留用户原话 |

普通音乐和视频配乐不会混用模型：ACE-Step 不直接理解视频，GVMGen 也不会替代普通音乐生成。这种边界清晰的设计有利于保证各条能力的可维护性和结果可解释性。

## 2. 项目的核心优势

### 2.1 从“一句话生成”升级为“可编辑的情绪叙事”

MoodTrack 最具辨识度的能力是情绪轨道。用户可以为一首作品设置多个节点，并分别编辑：

- 情绪名称，例如“压迫”“期待”“释然”；
- 节点出现的时间；
- 每个节点的情绪强度；
- 整体情绪描述，例如“失落但最后充满希望”。

这使用户表达的不再只是“生成一首悲伤的歌”，而是“从克制的低落开始，在中段建立期待，最后得到温和释放”。系统将这条创作意图保留为音乐生成的可编辑上下文，因此比单一标签更适合短片、游戏剧情、品牌叙事和个人创作。

### 2.2 局部重绘是“修改作品”，而不是“重新抽一首”

很多 AI 音乐工具只能重新生成整首作品；一旦副歌不够有力、某一段鼓点不合适，用户必须重新开始，之前满意的部分也会丢失。

MoodTrack 的局部重绘允许用户：

- 选择要修改的开始与结束时间；
- 用自然语言描述只希望改变什么；
- 调整修改强度；
- 保留源音乐、已生成歌词和未选中区间；
- 在新旧版本之间对比并选择主版本。

在技术上，局部重绘会把已生成音频作为受控源音频传给 ACE-Step，并传递修改区间、重绘强度与交叉淡化参数。其目标不是“重新生成一首相似的歌”，而是在已有作品的连续性上完成定点修改。对于“副歌再有冲击力一些”“30 秒后加入弦乐推进”“保留主唱旋律但弱化鼓点”等迭代型需求，这是一种更接近真实制作流程的交互方式。

### 2.3 预设场景与自由 Prompt 并存

系统提供深夜驰骋、毕业回忆、史诗战斗、品牌发布等场景预设，帮助没有音乐制作经验的用户快速起步；同时提供自由场景，允许用户直接输入自己的创作 Prompt，不强行套用既有场景的乐器、类型或叙事。

这种设计兼顾了两类用户：

- 新手可以通过预设迅速获得可用的制作方向；
- 有明确想法的创作者可以直接控制编曲、音色、节奏、动态和禁用元素。

### 2.4 情绪解释可见，而不是黑盒标签

Text Emotion Agent 会对用户输入的自然语言进行归纳，并在页面上展示结果。它不是额外的音乐生成模型，而是一套确定性、多语言的情绪归一化规则：它将“雨天的孤独感”“失落但充满希望”等开放式描述转换为主情绪、辅助情绪及置信度，同时保留原始文本。

其价值在于：

- 降低用户表达方式不同带来的理解偏差；
- 让系统的情绪判断可以被看到、被修改、被解释；
- 当分类置信度不足时保留用户原句，而不是强行套入错误类别。

### 2.5 每次生成都具有版本独立性和防旧结果保护

MoodTrack 在生成任务、播放器地址和音频校验上都采用了新鲜性保护。每次请求会使用新的任务标识、随机种子和防缓存参数；服务端响应禁止缓存；前端还会校验 WAV 结构、实际时长和音频 SHA-256 指纹。

因此，系统会拒绝把旧文件、重复文件、时长明显错误的文件伪装成新生成结果。对用户而言，这意味着“重新生成”确实应得到一份新的结果，而不是播放器缓存或任务串用造成的假更新。

### 2.6 本地模型带来的隐私、响应可控性与稳定性

普通音乐生成运行在本机 ACE-Step 服务中，主模型和歌词模型都只监听本机回环地址，再由受控网关向页面提供能力。这样可以避免把本地模型端口直接暴露到公网，并减少第三方云端排队对创作节奏的影响。

系统还通过守护脚本分别监控网页入口、ACE-Step、GVMGen 和公网隧道。普通音乐和视频服务独立运行，某一条链路出现问题时，不应无关地影响另一条链路。

### 2.7 视频配乐采用独立视觉到音乐管线

视频配乐并不是把视频“伪装成音频”交给 ACE-Step，而是由 GVMGen 读取视频帧进行生成，再由 FFmpeg 合成带新音乐的视频。浏览器会先在本地完成轻量画面分析，页面展示节奏、能量和视觉变化；实际视频到音乐推理由独立 GVMGen 服务完成。

对于大视频文件，系统可使用对象存储直传，避免文件先经过公网隧道慢速回传到本机。这是产品在实际可用性上的重要优势：生成体验不仅取决于模型，也取决于上传与作业链路是否可靠。

## 3. 当前“音乐情绪起伏不明显”的原因

情绪起伏不明显是当前生成式音乐技术中较典型的限制，并不等同于没有调用 ACE-Step、没有更新音频或返回了缓存。当前版本确实会把情绪轨道写入 ACE-Step 的生成 Prompt，但这条轨道目前仍属于“文本条件”，而不是可以逐秒精确执行的自动化控制曲线。

主要原因如下。

| 技术原因 | 当前系统的真实行为 | 对听感的影响 |
|---|---|---|
| 情绪轨道是文本提示 | 时间、情绪标签和强度会被压缩为一段文本，例如某秒开始“紧张 70%” | 模型会理解整体叙事，但不能保证在精确秒点产生等比例的音量、配器或和声变化 |
| 长音频优先追求整体连贯 | ACE-Step 一次性生成整段音乐，需要维持节拍、调性、音色和结构一致 | 模型往往倾向平滑过渡，避免出现突然割裂的段落 |
| 文本条件之间存在优先级竞争 | 场景、编曲、乐器、禁用元素、总体情绪、原始描述和情绪轨道都会进入同一生成语义空间 | 具体的情绪变化可能被更强的风格或配器描述稀释 |
| 当前使用快速 Turbo 配置 | 本地使用 Turbo 模型和固定的 8 步推理，重点是以可接受的本地时延完成高质量生成 | 速度与可控性的平衡并不等价于逐段精确编曲控制 |
| 生成带有随机性 | 每次任务使用随机种子，保证新版本不被固定复用 | 同一 Prompt 的“高潮感”并不会在每次生成中以完全相同方式出现 |
| 情绪词本身较抽象 | “希望”“释然”“紧张”不是直接的声学控制参数 | 模型需要自行把抽象情绪翻译成节奏、和声、密度、音色和动态，结果会存在主观差异 |
| 当前不使用参考音频 | 这是当前的明确产品配置：完整生成和重绘都不注入情绪参考音频 | 音乐更独立、更不易受参考风格束缚，但对文本 Prompt 的依赖更高 |

需要特别说明：当前“强度 80%”并不等价于音量精确提高 80%，也不等价于某一秒一定出现鼓组、转调或高潮。它表达的是生成意图的权重，而不是数字音频工作站中的自动化轨道。

## 4. 为什么局部重绘仍然是目前最有价值的修改手段

在现有生成模型条件下，局部重绘比重新生成整首音乐更适合处理“情绪没有起来”的问题。

例如，当用户觉得 30 至 45 秒不够高潮时，可以明确指定：

“保留人声旋律和前后节奏；在 30 至 45 秒加入更密集的鼓组、上行弦乐和铜管回应，形成明显推进，但不要改变其他段落。”

相比把整首 Prompt 改得更夸张后重新抽取，局部重绘有三个优势：

1. 变化范围明确，已经满意的段落不会被无故丢失；
2. 指令集中，模型不必同时重新处理全曲所有结构；
3. 可以通过重绘强度在“保留原作”与“大胆修改”之间选择。

它也存在边界：如果问题来自整首作品的基础结构太平、速度不适合或主旋律缺乏高潮，仅重绘一小段未必足够。此时重新生成，或采用后续的分段生成方案，会比反复局部修改更合理。

## 5. 现阶段的技术取舍

MoodTrack 当前选择的是“可用性、原创性、实时交互和可解释性优先”的路线。

- 不使用情绪参考音频：减少风格复制和素材依赖，保障每次以用户文本为主要创作来源；代价是情绪风格的稳定锚点更少。
- 使用单次长音频生成：保证全曲节奏与音色连续；代价是逐段动态的精确度低于逐段人工编曲。
- 使用本地 Turbo 推理：减少云端排队和网络依赖；代价是不能把“速度快”简单理解为“每一个微观细节都最强”。
- 使用随机种子：保证生成不复用旧版本；代价是结果具有探索性，需要版本比较与筛选。
- 使用局部重绘：提高迭代效率；代价是无法完全替代传统多轨制作或人工混音。

这些并不是系统故障，而是当前产品在创作自由度、生成速度、结果一致性与计算成本之间做出的工程平衡。

## 6. 下一阶段可提升情绪起伏表现的方向

要让“情绪轨道”从创作提示进一步变成可听见、可验证的音乐结构，应从文本提示走向更强的时间控制。建议的演进方向如下：

1. 分段生成与结构拼接：把前奏、发展、高潮、结尾分别作为带衔接约束的片段生成，再进行平滑拼接。这样能显著增强段落差异，但需要解决节拍、调性、主旋律和混音连续性。

2. 情绪到编曲动作的显式映射：不只写“紧张 80%”，还将其映射为“提高节奏密度、增加低音持续音、缩短鼓点间隔、减小混响空间”；将“释然”映射为“减少打击乐、放宽和声、延长尾音”。这会让抽象情绪变成更可执行的音乐控制。

3. 强化 Prompt 分层：将核心创作方向放在最高优先级，减少重复、冲突或过长的文本条件，避免场景预设和用户自由描述互相削弱。

4. 多候选生成与排序：一次生成少量候选，利用音频能量、频谱密度、节拍变化和人类偏好评分共同筛选，而不是把单次结果直接视为最终答案。

5. 情绪可控性评价：为每个生成结果计算分段响度、节奏密度、频谱重心和配器密度，并与用户设定的情绪曲线比较。它不能代替人耳判断，但能发现“全曲几乎没有动态变化”的明显问题。

6. 为用户提供创作取向选择：例如“整体连贯优先”“戏剧起伏优先”“人声清晰优先”。这样用户能够主动选择稳定性与变化幅度之间的平衡。

## 7. 对外沟通时建议使用的表述

MoodTrack 的优势不在于承诺“任何情绪曲线都能逐秒精确实现”，而在于把通常不可控的一次性音乐生成，变成可定义、可编辑、可局部修改、可对比版本、可重新生成的创作流程。

可以将其概括为：

> MoodTrack 以可编辑的情绪轨道组织创作意图，以本地 ACE-Step 生成原创音乐，以局部重绘完成定点迭代，并以独立的 GVMGen 视频配乐链路覆盖视频场景。它的核心价值，是让用户从“抽一首歌”走向“持续把一首歌改到更接近想法”。

## 8. 结论

MoodTrack 已具备完整的 AI 音乐创作闭环：情绪表达、场景选择、自由 Prompt、纯音乐或人声歌曲、自动歌词、音频生成、局部重绘、版本比较、视频配乐和结果下载。

其中最有竞争力的部分是局部重绘与情绪轨道：前者让生成结果可继续制作，后者让用户能够表达“音乐应该怎样变化”。当前情绪起伏不够明显，主要受限于长音频文本条件生成的技术形态，而不是缓存、模型未加载或参考音频配置错误。未来通过分段控制、显式编曲映射和候选排序，可以将情绪轨道从“语义意图”进一步提升为“更强的时间结构控制”。
